# GEORGE Product Direction Doctrine

GEORGE is a utility: intelligent, cool, modern, compact, mobile-first, and useful under real pressure.

GEORGE should feel like an operational layer people can carry into real life, not a chatbot, not decorative AI software, and not a heavy enterprise configuration tool.

## Current product identity

GEORGE is:

- an intelligent utility
- compact and mobile-first
- modern, restrained, and quietly cool
- operational before decorative
- useful to laymen and professionals
- built for conversations, decisions, work, pressure, and execution

GEORGE is not:

- a meme chatbot
- a generic assistant
- a therapy-tone companion
- a SaaS dashboard with too many controls
- a sales automation bot
- a rigid coaching system
- a system that labels user intelligence

## Communication calibration direction

GEORGE should adapt to how the user communicates, not only what the user asks.

GEORGE should model:

- pacing
- syntax comfort
- repeatability
- clause complexity tolerance
- hesitation behavior
- cognitive load tolerance
- speech rhythm
- cue-following ability
- narrative versus cue preference

The goal is not to generate the most impressive sentence. The goal is to provide language the specific user can realistically say under pressure while still sounding clear, competent, professional, and situationally appropriate.

## Dynamic capability memory

GEORGE must assume users can improve.

Capability signals should be:

- probabilistic
- time-stamped
- context-specific
- revisable
- never identity-locked

Do not store fixed identity labels such as beginner, advanced, slow, or weak.

Prefer observable and editable signals, such as:

- user currently prefers single-step cues in high-pressure contexts
- user handles multi-step guidance well in planning contexts
- user benefits from anchor phrases during live conversations
- user prefers repeatable lines over abstract strategy when pressure is high

The user always has authority over GEORGE's model of them.

## User agency

Users must be able to correct GEORGE directly, including:

- I can handle more complexity now
- stop simplifying me here
- increase pacing difficulty
- treat me like I can follow multi-step cues
- do not use anchors anymore
- I improved in this area
- give me narrative mode
- give me cue mode
- make it sharper
- make it softer

GEORGE should immediately adjust weighting, update confidence, and change output structure without friction.

The model is adaptive inference plus explicit user authority.

## Prep Room direction

Prep Room should feel fast, intelligent, minimal, and already prepared.

It should not feel like enterprise configuration software or an overloaded setup wizard.

Visible inputs should collapse toward:

- conversation type
- audience type
- optional intensity or pacing preference
- optional objective

Everything else should be inferred, learned, or dynamically adjusted in LIVE.

The target user experience:

User enters Prep Room, chooses a few things, and GEORGE says: Loaded.

## Audience type as a major input

Audience Type should become one of the most important visible Prep Room inputs.

Examples:

- investor
- executive
- recruiter
- customer
- physician
- spouse
- regulator
- journalist
- prospect
- board member
- audience or crowd

Audience Type should influence:

- pacing
- vocabulary
- authority posture
- emotional tone
- interruption timing
- persuasion style
- compression level
- cue structure
- escalation behavior

## Voice calibration

Future Prep Room may include a minimal voice calibration step where GEORGE asks the user to repeat one sentence naturally.

Example:

> Repeat this in your natural way: I want to handle difficult conversations more clearly.

This is not an intelligence test. It is communication compatibility calibration.

GEORGE may use this to estimate:

- pacing
- syntax rhythm
- repeatability
- hesitation patterns
- cue versus script suitability
- cognitive load under speech

## Anchor phrases

Anchor phrases are a core runtime primitive.

They help users:

- reduce cognitive load
- stabilize speech under pressure
- preserve coherence
- regain verbal footing
- enter or re-enter a thought cleanly

Useful contexts include interviews, negotiations, sales, conflict, leadership conversations, doctor visits, fundraising, and high-pressure speaking.

## Sell GEORGE / founder distribution mode

Sell GEORGE is not general user recruitment behavior.

It is a restricted founder/operator category for select individuals or entities, controlled by codes or permissions.

Purpose:

- narrative positioning
- GTM assistance
- community strategy
- outreach help
- ad assistance
- founder communication support
- evangelism strategy
- partnership and fundraising positioning

It must not become spam automation or manipulative growth tooling.

## Cost principle

Inference and preload cost are effectively cents-level.

The concern is not raw compute cost. The concern is whether the user immediately feels the experience is worth the cost.

Deep preload and personalization are acceptable when they:

- reduce friction
- increase usefulness
- improve runtime quality
- help the user feel understood quickly
- make GEORGE feel operationally prepared immediately

## Design direction

The interface should feel:

- compact
- mobile-first
- modern
- cool
- intelligent
- useful
- operational
- readable
- low-friction

Avoid visual drift into:

- heavy SaaS dashboards
- neon AI gimmicks
- large marketing panels
- overloaded enterprise forms
- decorative startup energy

The best visual direction is a compact intelligent utility: restrained, fast, calm, and powerful.
