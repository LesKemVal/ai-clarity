# Legacy Pro LIVE Adapter Pattern

Pro LIVE is currently shelved.

Some old data structures may still appear in the codebase from earlier Pro LIVE work. Those structures should not govern current GEORGE behavior.

## Current Rule

Current runtime has two active experiences:

- Normal GEORGE
- LIVE GEORGE

Anything from old Pro LIVE should be treated as dormant unless deliberately reinstated.

## Adapter Principle

If old Pro LIVE data appears, do not treat it as an active product mode.

Instead, translate only the useful human-conversation primitives into individual LIVE support.

Reusable primitives include:

- pressure handling
- timing
- tone
- cadence
- objection or resistance handling
- clear next-move guidance
- service-call support
- operator-style wording assistance
- boundaries and careful phrasing when needed

Do not revive:

- firm mode
- campaign management
- CRM structures
- team workflow assumptions
- sales-pipeline governance
- organization-level control surfaces

## Telephone / Service Operator Path

Old Pro LIVE logic may eventually help individual telephone or service operators.

The correct frame is not campaign execution.

The correct frame is:

- help the individual operator handle the current call
- stay calm and clear
- ask better clarifying questions
- de-escalate when needed
- provide short usable lines
- preserve trust and professionalism
- avoid over-talking
- keep the next move simple

## Future Reinstatement Rule

Pro LIVE can be reinstated later only as a deliberately separate runtime.

Before reinstatement, define:

- who the user is
- what data is collected
- what firm or team controls
- what is visible to the individual user
- what compliance boundaries exist
- how normal GEORGE and LIVE GEORGE remain separate

Until then, Pro LIVE stays isolated.
